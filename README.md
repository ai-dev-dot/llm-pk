# LLM PK — 大语言模型对战游戏集合

一个专门存放「由大语言模型直接对战(PK)的游戏集合」的项目。

每款游戏由多个大语言模型(LLM)分别扮演对弈的双方(或各方)角色,在 Web 页面上实时展示完整对局过程。每场对局都会留下详细日志,支持回放与复盘分析。

## 项目理念

本项目围绕三个核心理念构建:

- **规则即裁判** —— 游戏规则明确无歧义,胜负判定客观清晰,由规则一锤定音,而非人为主观判断;
- **思维可见** —— 不只展示落子、出牌等行动,还尽可能展示模型的思考过程,让"智力"本身被看见;
- **一切可回放** —— 每场对局都留下完整日志,可逐回合回放、复盘、分析,事后可以追溯每一刻。

## 通用约定

所有收录进本项目的游戏,必须遵守以下四个约定。

### 约定一:规则清晰,胜负分明,对人类友好

1. **规则明确无歧义** —— 游戏规则必须在任何局面下都给出唯一、一致的解释与判定,不存在灰色地带;
2. **胜负客观可判定** —— 胜负必须**清晰、可由规则自动裁定**,不依赖任何主观评价;
3. **对人类极其友好** —— 规则简单、直观,人类玩家容易理解、容易上手;
4. **取材人类熟悉的游戏** —— 优先采用人类熟知的经典游戏形式(棋类、牌类、策略类等),降低所有人的理解门槛。

### 约定二:多角色对弈,Web 页面展示

1. **至少两方对弈** —— 每款游戏包含对弈的双方,可扩展支持多方;
2. **一模型一角** —— 每个角色由一个 LLM 独立驱动,角色之间互不共享状态、互不干扰;
3. **Web 实时展示** —— 对局过程通过 Web 页面实时展示(棋盘、牌面、行动序列等),供观看、围观;
4. **尽量展示思考过程** —— 在条件允许时,展示模型的思考过程(如推理轨迹),让对局不只是结果的较量。

### 约定三:对局过程详细日志

1. **全程记录** —— 完整记录对局过程,包括每个回合、每步操作、发生的时间、决策的依据;
2. **结构化、可机器解析** —— 日志采用结构化格式,便于程序读取与后续处理;
3. **服务于复盘与分析** —— 日志是复盘、分析的基本素材:可用于对比不同模型的表现、统计策略倾向、排查异常行为等。

### 约定四:对局回放

1. **必须支持回放** —— 每款游戏都提供对局回放能力;
2. **逐回合可追溯** —— 回放基于对局日志构建,可从头逐步重放,可定位到任意回合、任意步骤;
3. **回放与日志同源** —— "看到的回放"与"当时的日志"完全一致,保证可追溯、可验证。

## 目录结构(建议)

```
llm_pk/
├── README.md            # 项目说明与通用约定(本文件)
├── CLAUDE.md            # AI 协作者开发约定
└── games/
    └── <game_name>/       # 每个游戏一个独立目录
        ├── rules.md       # 游戏规则说明
        ├── src/           # 游戏引擎 / 判定代码
        ├── web/           # 对局展示页面
        └── logs/          # 对局日志与回放数据
```

## 添加新游戏

1. 在 `games/` 下新建游戏目录,先书写 `rules.md` 并自检:规则是否无歧义、胜负是否可自动裁定;
2. 实现多角色对弈逻辑(每个角色接入一个 LLM)与 Web 展示页;
3. 确保对局全程写结构化日志,并实现基于日志的回放;
4. 回归四个约定,确认全部满足后再收录。
